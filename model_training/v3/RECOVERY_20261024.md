# Training recovery on the RTX 5090 — 24 October 2026

The training pipeline is repaired and a genuine fine-tune of the original
classifier has completed. **The production Android model is retained:** the
candidate does not improve Healthy recognition in the complete app replay.
Training correctness and deployment benefit are separate acceptance decisions.

the original checkpoint. The checkpoint actually exists on the owner’s PC at

## Confirmed implementation defects repaired

- AdamW and EMA were reconstructed inside the epoch loop. Optimizer moments and
  EMA history now persist across epochs, including the unfreezing boundary.
- Resume loaded model weights but ignored the saved optimizer/scheduler. New
  checkpoints retain online weights, EMA, optimizer, scheduler, RNG and global
  step. Resume checks config, data manifest and cache identity. Legacy weights-only
  continuation is explicitly a new initialization, not an exact resume.
- Layer LR assignment could exclude an unfrozen final norm and reversed the usual
  depth decay. All intended parameters now have positive, explicit groups, with
  lower rates for earlier layers and full coverage for later unfreezing.
- “Uniform” sampling still divided weights by group size and sampled with
  replacement. It now uses the natural item distribution without replacement;
  optional class/source balancing remains explicit.
- Existing classifier initialization was absent. `--init-checkpoint` now validates
  architecture, input size, exact semantic label order and strict state loading.
- The run directory could be overwritten; non-resume runs now require a new name.
  Inputs require uint8 NHWC cache shape, aligned indices and disjoint split groups.
- Checkpoint selection could trade disease recognition for Healthy. Fine-tuning
  now compares each disease’s recall, Other recall and false Healthy rate against
  the frozen initialization before accepting a checkpoint. This is a development
  guardrail, not a replacement for statistical app/deployment acceptance.
- Evaluation could append duplicate/stale results. Resume now verifies model bytes,
  dataset, implementation and policy identity; incomplete/error results fail.
  Paired comparisons reject missing coverage, duplicates and mismatched references.
- Reliability bins could double-count boundary confidence. Bin membership is now
  exclusive. Mixed-label scenes are excluded from scalar photo accuracy/rejection
  denominators while retaining their object diagnostics.
- Export now exercises standardized real inputs and validates semantic labels.
  Bundle provenance distinguishes original-weight fine-tuning from fresh-head
  retraining. Canonical sparse resize accelerates replay without changing weights.

No new 0–255 normalization defect was established in the checked-in corrected
v3 code. Both its training and evaluation paths divide raw pixels by 255 before
ImageNet normalization. The older v2 expression with 255-scaled mean/std is
algebraically equivalent. This repair does not claim those valid expressions
caused the earlier failed run. The historical report describes earlier invalid
runs; those claims were not independently recreated in this recovery.

## Controlled checks and training

`recovery_checks.py` fits a 27-example, nine-class control and verifies real GPU
interruption/resume. It reached 100% tiny-training accuracy in six head updates.
Three continuous epochs and an interrupted/resumed counterpart produced exactly
identical online and EMA parameters (maximum absolute difference zero). Optimizer
step counts persisted through head warm-up and block unfreezing.

Main run: `recovered_head_20261024`, recovered original checkpoint, head only,
ordinary CE, natural sampling, no smoothing/augmentation, FP32, head LR `1e-5`,
three epochs, batch size 64. The original backbone was frozen. An independent
three-epoch class-sampling control changed only the sampling setting.

On the 1,277 selection-validation **cached crops**, the natural-sampling run gave:

| Metric | Frozen original | Selected epoch 2 |
| --- | ---: | ---: |
| Raw crop accuracy | 87.94% | 93.89% |
| Healthy recall | 86.0% | 86.0% |
| False Healthy among non-Healthy crops | 4.48% | 1.47% |

All three natural-sampling epochs passed the development retention checks.
A final controlled one-block comparison reached 92% crop Healthy recall but
failed the Leaf Miner retention gate and was not promoted.
Class balancing with a frozen backbone raised crop Healthy recall to 88%; its later checkpoints failed
the Leaf Miner retention gate and were not promoted. These results establish
stable adaptation, not a new independent generalization estimate.

224x224 NHWC float32 contract. Across 16 real cached inputs and one standardized
random input, the worst PyTorch/TFLite logit difference was `3.58e-6`, with no
label disagreements. Candidate TFLite SHA-256:
`ccda3745d0b91f501936081087192c528f61ce7e8fdddcebf0253ddb4e92dd52`.

Production calibration and plant decision policy were held fixed. Both models

692 photos. There were 441 source groups, not 693 independent plants.

The old locked test was already opened during the previous experiment. It was

## Reproduce and continue

Use the owner’s existing `~/.venvs/agribot-train` environment on the PC. A new
run name is required for a fresh experiment; use `--resume` only with the same
schedule/configuration and new-schema full-state checkpoint.

```bash
python model_training/v3/recovery_checks.py \
  --checkpoint /home/genesis/sakshyam-agribot/v2/runs/field_vits2/best.pt \
  --work ~/agribot-data/work --out ~/agribot-data/new-recovery-check

python model_training/v3/train.py --run-name recovered-head-new-run \
  --init-checkpoint /home/genesis/sakshyam-agribot/v2/runs/field_vits2/best.pt \
  --epochs 3 --warmup-epochs 1 --unfreeze-blocks 0 \
  --lr-head 0.00001 --lr-backbone 0.000001 --bs 64 \
  --no-augment --precision fp32 --drop-path 0
```

## Remote continuity

The owner’s laptop and PC are connected through Tailscale. The laptop has the
local SSH alias `agribot-5090`, a dedicated local key, strict trusted host-key
checking and keepalives. No private key or account credential is committed.
Windows Tailscale is Automatic/Running with unattended mode enabled; the PC’s
Tailscale service is enabled. The PC’s existing AC suspend policy is `nothing`.

The persistent `agribot` tmux session is independent of SSH. From the configured
laptop, `ssh -t agribot-5090 'tmux attach -t agribot'` opens it. A local ignored
`.toolchains/ssh/Connect-Agribot.ps1` retries transport failures and reattaches.
Jobs require their actual training command to run inside tmux, as the recovery,
export and replay commands did. A finished job is not described as still running.

The laptop needs an internet connection (the owner will use hotspot) and both
devices must remain powered on. SSH transport may reconnect after a network
change; tmux preserves remote processes. This does not guarantee Codex execution
while its own laptop is offline or asleep, nor survival of PC power loss/reboot.
